# Prism Research — 2026-08-10

Web research pass across the four required source classes. Backlog items
already logged in `.prism/routine_log.md` from the 2026-08-07 runs are
carried forward and re-validated against fresh search results rather than
re-discovered from scratch.

## 1. Industry practice

- Agentic analytics is the dominant 2026 framing: "40% of enterprises
  adopting [agentic tools] for proactive insight generation and anomaly
  detection" per aggregated industry coverage. The expected shape is a
  pipeline of narrow deterministic detectors feeding an LLM narration/
  reasoning layer that turns raw signals into prioritized, actionable
  language — not an LLM doing the detection itself. This validates Prism's
  existing pattern (Auto-Insights: pure-Python detectors + optional Gemini
  narration) and argues for extending the *same* pattern to
  `modules/anomaly.py`, which currently only emits a templated
  `anomaly_reason` string with no narrative layer.
- Data-analyst/data-scientist job descriptions (general 2026 postings)
  continue to weight "communicates findings to non-technical stakeholders"
  and "data quality / governance" as core, testable skills alongside
  Python/SQL/stats — a narrated, exportable data-quality artifact is a
  direct interview-relevant deliverable, not just a UI nicety.

## 2. Competitor tools

- Landscape as of mid-2026: chat-first tools (ChatGPT Advanced Data
  Analysis, Julius AI) win on fast natural-language-to-chart/narrative;
  notebook tools (Hex, Deepnote) win on becoming a durable team asset.
  None of the four surveyed reference sources describe a first-class,
  exportable **data quality scorecard** as a standalone artifact — most
  quality-scoring in these tools is implicit/inline, not a shareable
  deliverable. That's a gap Prism can differentiate on: it already computes
  a fully explainable weighted 0-100 Data Health Score
  (`data_engine.get_health_breakdown`) but has never made it exportable —
  the existing `report.py` HTML export bundles quality metrics into a
  kitchen-sink Auto-EDA report, not a focused, stakeholder-shareable
  scorecard.
- None of the surveyed competitors narrate anomaly detections in plain
  English with a suggested next action tied to a specific flagged-row
  reason set — this remains a genuine differentiator opportunity for
  Prism's existing IsolationForest anomaly detector.

## 3. Ecosystem tech

- No new dependency need identified this cycle. Both selected features
  are deterministic-first (pandas/numpy for the scorecard grading logic,
  existing `google-generativeai` client for the narration layer, reusing
  the exact `call_gemini()` call path already hardened in the last two
  runs). Zero new packages required — keeps requirements.txt stable,
  keeps effort at S/M instead of L.
- polars/DuckDB large-file path: still open, still flagged by both prior
  runs as architecture-adjacent; not revisited this cycle, no new
  information changes that assessment.

## 4. Agentic EDA research

- Recent papers (DataSage, QUIS: "Question-guided Insights Generation for
  Automated EDA", the DMAIC-inspired industrial anomaly agentic system)
  converge on the same three-stage shape: **detect (deterministic) ->
  diagnose/structure (still deterministic or lightweight) -> narrate
  (LLM)**, with the LLM stage explicitly scoped to *language generation
  from structured evidence*, never to re-deriving the evidence itself.
  This is exactly the shape of the anomaly-narration feature selected
  below: the flagged-row set and per-row reasons stay 100% deterministic
  (`IsolationForest` + median-deviation reasoning, already shipped); only
  the final paragraph is delegated to Gemini, capped to summary statistics
  (reason counts, not raw row values) to stay both PII-safe and
  free-tier-cheap.
- "Self-verifying analysis agents" (a recurring theme, and the basis of
  Prism's own Insight Verifier shipped 2026-08-07) reinforces caching:
  narration should be computed once per stable input and cached, not
  regenerated on every rerun. Applied here via a fingerprint-keyed
  `st.session_state` cache for anomaly narration, mirroring the guardrail
  ("design for rate-limit handling and caching") explicitly required by
  this routine.
