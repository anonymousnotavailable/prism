## Industry practice
- [Data Analyst Skills 2026 — LoopCV](https://www.loopcv.pro/skills/data-analyst/) /
  [500 job posts analyzed — Medium](https://medium.com/ai-analytics-diaries/i-analyzed-500-data-science-job-posts-in-2026-heres-exactly-what-they-want-eaac5980590b):
  ML appears in 69% of data-scientist postings (3rd most-demanded skill
  behind Python/SQL); data-analyst postings still center on SQL, dashboards,
  statistics, and "data storytelling" — i.e. the ability to narrate findings
  in plain English, not just produce them. Directly supports this cycle's
  agentic-analysis priority: a tool that narrates its own findings is
  demonstrating exactly the skill panels screen for.

## Competitor tools
- [Julius AI vs Deepnote vs Hex vs ChatGPT — 2026 comparisons](https://gudz.ai/posts/ai-data-analysis-tools-2026):
  Julius/ChatGPT win on fast ad-hoc CSV analysis with plain-English
  explanations; Hex/Deepnote win on structured, collaborative notebooks.
  None of the compared tools specifically narrate *unsupervised anomaly
  detection* output in plain English — they narrate summary statistics and
  chat answers, but flagged-outlier explanation is typically left as a raw
  table. This is a real, if narrow, differentiation opening — confirms this
  run's pick isn't just internal-backlog busywork.

## Ecosystem tech
- [Pandas vs Polars vs DuckDB — 2026](https://www.analyticsinsight.net/programming/pandas-vs-polars-vs-duckdb-what-data-scientists-should-use-in-2026):
  reconfirms the Run 1/Run 2 backlog item — Polars for heavy in-memory
  transforms, DuckDB for file-backed/larger-than-RAM analytical queries.
  Prism's SQL Lab already uses DuckDB; the main pandas pipeline still
  doesn't. Still open, still architecture-adjacent — not touched this run.

## Agentic EDA research
- [arXiv 2510.04023 — LLM-Based Data Science Agents survey](https://arxiv.org/pdf/2510.04023)
  and [Databricks: What is Agentic Analytics?](https://www.databricks.com/blog/what-is-agentic-analytics):
  both flag **self-verification of agent output** as the field's central open
  problem — LLM-generated analysis hallucinates numbers even when the
  underlying computation was correct. Prism's `insight_verifier.py`
  (shipped Run 1) already addresses exactly this for Auto Analyst's
  findings. Anomaly Narration (this run) intentionally does NOT need the
  same treatment: it narrates a *count and category of flagged rows*, not
  numeric claims about the dataset, so there's nothing equivalent to
  fact-check — noted here so a future run doesn't mistake this for a gap.
