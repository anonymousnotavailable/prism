## Atlas voice: existing state before this run

`modules/voice_input.py` already existed (added in an early pre-numbered
run, `2c5d8dd "Add persistent Atlas side panel with voice..."`), wired
into both Atlas mic call sites in `app.py`. It wraps
`streamlit_mic_recorder.speech_to_text()`, which:

1. Records raw audio in the browser (MediaRecorder API).
2. Ships the audio bytes to the Streamlit Python process.
3. Calls `SpeechRecognition`'s `recognize_google()` — Google's free,
   undocumented, unauthenticated speech API, reached over the **server's**
   network, not the browser's.

Two real problems, not just a "missing Web Speech API" gap as the brief
assumed:

- `voice_input.is_available()` only checks whether the pip package
  imported — it has nothing to do with whether the visitor's browser
  actually supports speech recognition. The gate is at the wrong layer.
- The Python `SpeechRecognition` package's `recognize_google()` wraps its
  whole body in a bare `except: output=None` (confirmed by reading the
  installed package source at
  `/usr/local/lib/python3.11/dist-packages/streamlit_mic_recorder/__init__.py`)
  — any network failure, rate limit, or malformed response silently
  produces no transcript, indistinguishable from "the user hasn't spoken
  yet." In this sandbox specifically, that endpoint is almost certainly
  unreachable (proxy-only egress), so the existing voice path likely never
  produces a transcript here at all — though this can't be fully confirmed
  without a live deployment with real egress.
- `modules/voice_input.py` had **zero test coverage** anywhere in `tests/`.

This run's Web Speech API slice (see the run report) replaces this
mechanism with the browser's native `SpeechRecognition` API — feature-
detected client-side (the only place that can actually know), no server
round-trip, no third-party network dependency for transcription.

## Other genuinely new findings this run

1. **`modules/stats_lab.py` had zero test coverage** — a module that
   drives real user-facing statistical verdicts (t-test, ANOVA,
   chi-square, Pearson) had never been directly tested. `grep -rl
   "from modules.stats_lab\|from modules import.*stats_lab" tests/` came
   back empty. Fixed by adding `tests/test_stats_lab.py` (45 tests,
   covering both the pre-existing functions and this run's new additions).

2. **`normality_warnings()` was a dead end** — `stats_lab.py` could
   already tell a user "this test's normality assumption looks shaky" but
   offered no valid alternative test to run instead. This run's second
   feature (non-parametric alternatives) closes that gap. See the run
   report for full reasoning.

3. **Sign-convention bug caught before merge**: the first draft of
   `run_mannwhitney()`'s rank-biserial effect size used
   `r = 1 - 2U/(n1*n2)`, which put the sign backwards relative to the
   function's own reported group medians (a group entirely below another
   came out as `r=+1` instead of `-1`). Caught by
   `test_run_mannwhitney_rank_biserial_sign_direction` before merging;
   fixed to the standard `r = 2U/(n1*n2) - 1` (Kerby 2014) convention.

4. **Web Speech widget iframe height clipping (found + fixed same run)**:
   the "voice unsupported" caption (2-3 lines wrapped) was clipped by ~3px
   against the `components.html()` iframe's fixed `height=58` on a real
   Playwright screenshot at mobile width. Confirmed via
   `element.scrollHeight` (61px) vs. the iframe's rendered height (58px).
   Fixed by bumping the default `height` to 68px before merging — caught
   by the Phase 5 screenshot review this run's Playwright fix made
   possible, not by unit tests (which can't see rendered layout).

5. **Synthetic-Enter-keypress assumption disproven by real Playwright
   automation**: the original design for delivering a voice transcript
   into Atlas's text pipeline assumed a synthetic `KeyboardEvent('Enter')`
   would trigger Streamlit's `chat_input`/`st.form` submission, matching
   real-user Enter-to-submit behavior. A real headless-Chromium test
   proved this false — the value lands (React sees the change) but no
   submission fires. Fixed by finding and `.click()`-ing the widget's own
   submit control instead (chat_input's send button /
   `st.form_submit_button`), verified working end-to-end in the same
   Playwright session before it was baked into `modules/web_speech.py`.
   Documented in the module's own comments so a future run doesn't
   reintroduce the Enter-key assumption.

No other genuinely new bugs found this run beyond what's listed above —
