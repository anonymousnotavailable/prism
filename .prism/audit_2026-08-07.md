# Prism Audit — 2026-08-07

Ran the app locally (`streamlit run app.py`, port 8765) with Playwright/Chromium
against the bundled Sales sample dataset, in both themes and at desktop
(1440×1000) and mobile-PWA (390×844) viewports. No `GEMINI_API_KEY` was
configured in this environment, which turned out to be a useful stress test:
every AI-touching flow was exercised in its "Gemini unavailable" degraded
path, not just its happy path.

## Findings

### 1. Critical — mobile PWA layout was broken by the fixed Atlas side panel
`.st-key-atlas_side_panel` (modules/theme.py) is `position: fixed`, `width:
328px`, paired with an inline `padding-right: 352px !important` on
`.block-container` (app.py, right after the panel's container). Neither
rule had a mobile breakpoint. At a 390px phone width that's negative usable
space: the nav pills, dataset banner, and every tab's content rendered
compressed into a ~60px vertical sliver with individual words wrapping
letter-by-letter, while the Atlas panel visually overlapped everything else.
Given the app's whole premise includes "installable on phone," this
directly undercuts the PWA claim — anyone opening Prism on a phone hit this
immediately, before ever reaching a feature. Screenshots:
`.prism/runs/2026-08-07/stats_lab_mobile_before.png` (this run, post-fix) vs.
the pre-fix state visible in `/tmp/m1.png`-era captures during triage
(not retained — see routine log for the before/after description).
**Fixed this run** — see CHANGELOG. A `@media (max-width: 768px)` rule
drops the fixed positioning so the panel falls into normal document flow
(full width, stacked) and cancels the inline padding override at matching
specificity (`div.block-container`).

### 2. Dependency — `google-generativeai` is fully end-of-life
Importing it now prints: *"All support for the `google.generativeai`
package has ended... switch to the `google.genai` package."* Every
Gemini-touching module (`ai_analyst`, `atlas`, `mllab`'s SHAP narration,
the new `hypothesis_engine`) is built on this SDK. It still works today,
but it will not receive security or compatibility fixes going forward, and
Google will eventually pull the plug on the old client outright. This is a
real migration, touching every `genai.GenerativeModel(...)` call site and
the exception types imported from `google.api_core.exceptions` — explicitly
out of scope for a single run under the "no architecture rewrites" guardrail.
**Logged as the top backlog item, not attempted.**

### 3. Cosmetic — light theme has several low-contrast dark-on-dark controls
In "Arctic (Light)": the nav pill bar, the bottom "Ask Atlas anything…"
input bar, and the "Ask by voice"/"Send" buttons in the Atlas side panel all
keep a near-black background with light-on-dark-ish text in a theme that is
otherwise a bright white/lavender palette (see
`.prism/runs/2026-08-07/stats_lab_desktop_light.png`). Not a functional
break — text is still legible — but visually inconsistent with the rest of
the light theme's glass system. Pre-existing, not touched this run (out of
scope: theming rules would need a broader pass across every themed control,
not a one-line fix). **Backlog.**

### 4. No broken flows found in the AI degraded paths
`ai_analyst`, `auto_analyst`, and `atlas` all handle a missing/invalid
Gemini key with a clear `GEMINI_SETUP_HELP` message rather than crashing —
confirmed live, not just by reading the code. This is the standard every
new AI feature this run was held to (see `hypothesis_engine`'s heuristic
fallback).

## What a hiring panel would probe (and where Prism already answers it)
- "How do you avoid p-hacking when testing many things at once?" — until
  this run, nothing in Prism answered this directly; Stats Lab required a
  human to pick one pair at a time. Addressed by this run's Hypothesis
  Engine (Benjamini-Hochberg FDR correction across the batch).
- "What happens when the LLM is wrong or unavailable?" — well covered
  (self-healing retry in `ai_analyst`, the rate limiter, and now the
  heuristic hypothesis fallback observed live in this audit).
- "Do you separate what the LLM decides from what's actually computed?" —
  yes, and it's a real pattern in this codebase (`autocleaner`'s SAFE/REVIEW
  split), now extended once more by `hypothesis_engine` (Gemini proposes,
  scipy/statsmodels decides).
