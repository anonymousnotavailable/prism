# Prism Audit — 2026-08-07

Quick end-to-end pass (Streamlit app launched locally, exercised via
Playwright, sample dataset `sales_data.csv`, no Gemini key configured in
this environment — so this also validated the "runs fully without a key"
claim).

## Confirmed working
- Landing screen, sample dataset loading, Overview tab (data quality,
  column health, drill-down), Atlas side panel and greeting all render
  correctly in both dark and light themes at desktop width.
- Auto Analyst tab's Gemini-setup warning displays correctly when no key is
  configured (`ai_analyst.GEMINI_SETUP_HELP`).
- New Hypothesis Engine section (this run's feature) renders and functions
  correctly in dark and light themes, heuristic fallback path exercised
  live (no key configured) — see `.prism/runs/2026-08-07/`.

## Bugs found
1. **[High] Mobile layout break** — the fixed-position Atlas side panel
   (`.st-key-atlas_side_panel`, styled in `modules/theme.py`) does not
   collapse or stack below ~640px viewport width. On a 390×844 phone
   viewport it overlaps essentially the entire main content column,
   leaving only a ~15px sliver of the actual tab content visible.
   Screenshot: `runs/2026-08-07/mobile_overview_dark.png`. This directly
   undercuts the "installable on phone" PWA claim in the README — not
   fixed this run (layout-CSS change wide enough in blast radius, across 6
   themes × every tab, to deserve its own dedicated run with full
   before/after screenshot verification rather than a rushed same-run fix).
2. **[Low] Light-theme leak on the chat input bar** — `st.chat_input`
   ("Ask Atlas anything...", fixed to the viewport bottom on every screen)
   keeps a hardcoded dark background under the "Arctic (Light)" theme.
   Screenshot: `runs/2026-08-07/hypothesis_engine_light.png`. Likely a
   missing CSS override for Streamlit's native chat-input shadow DOM under
   the custom theme — same reasoning as #1 for not fixing same-run (needs
   verification across all 6 themes, not just the two checked here).
3. **[Info] `google.generativeai` deprecation warning** — the installed SDK
   prints a `FutureWarning` recommending migration to `google.genai` on
   every import. No functional impact yet; flagged for a future dedicated
   migration run (the client/call shape differs enough that this isn't a
   drop-in swap).

## Weak spots vs. a hiring panel's likely probes
- Auto Analyst's "5 headline findings" are Gemini's own summary of its own
  step results — nothing statistically re-checks them. This run's
  Hypothesis Engine is a first step in the opposite direction (test, don't
  just narrate) but doesn't yet cross-check Auto Analyst's specific claims.
  Good next-run candidate: a lightweight critic pass over Auto Analyst
  findings using the same "verify with a real test" pattern.
- No large-file performance story — everything is a raw pandas DataFrame in
  session state; a multi-hundred-MB CSV would be slow end to end. polars/
  DuckDB-backed profiling (SQL Lab already uses DuckDB) is the natural next
  step and would be a strong interview talking point ("chose the right tool
  for scale, not just the familiar one").
