# Prism Audit — 2026-08-07

First run of the autonomous improvement routine. Launched the app locally
(`streamlit run app.py`, no `GEMINI_API_KEY` configured — deliberately, to
stress-test every fallback path), uploaded `samples/hr_data.csv` and
`samples/sales_data.csv`, and drove Overview, Anomaly Detection, and Stats
Lab through Playwright at desktop (1440x900) and mobile-PWA (390x844)
widths, in both Prism HUD (Dark) and Arctic (Light) themes.

## What already exists (do not rebuild)

Prism is far more built-out than the routine brief assumed. Confirmed
already shipped: Auto Cleaner, India Mode, Indian PII Vault, Hell Mode,
Auto Analyst (agentic "Run Full Analysis" — plan -> execute -> synthesize),
Atlas (JARVIS-style voice/typed router with two-phase destructive-action
guards, plan-then-act, Story Mode), Stats Lab (guided test selection),
Forecasting, Clustering, Domain Lens, Geo Lens, ML Lab with SHAP, SQL Lab
(full DuckDB workbench), a 15-dataset real-world corpus benchmark, and 5
custom dark/light themes. This is a deep bench — new work this run had to
add genuinely new capability, not reskin something that already exists.

## Bugs / weak spots found

1. **[FIXED this run] `stats_lab.suggest_test` crashes on `col_a == col_b`.**
   `run_pearson` calls `stats.pearsonr` on two identically-named columns,
   which pandas returns as a DataFrame instead of a Series, and scipy
   throws a raw `ValueError` with a shapes message no user should ever
   see. Unreachable from the Stats Lab UI itself (two separate selectboxes
   already prevent picking the same column twice), but very reachable from
   any future programmatic caller — which is exactly what this run's
   Hypothesis Engine's eval suite caught. Fixed with an explicit guard at
   the top of `suggest_test()`.

2. **[NOT FIXED — logged for next run, HIGH PRIORITY] Mobile-width layout
   collapse.** At a 390px PWA viewport, `st.columns()`'s main-content /
   Atlas-panel split doesn't reflow — the main content column gets
   squished to roughly 40px wide (every word wraps one character per
   line) while the Atlas panel keeps its desktop-sized min-width and eats
   the rest of the screen. Reproduces on every tab, with or without a
   dataset loaded — confirmed on the plain landing page and Overview both
   before and after any change in this run, so this is pre-existing, not
   caused by anything shipped today. `modules/theme.py` has zero
   `@media` breakpoints for narrow viewports today. Given the README's
   explicit "installable on phone... mobile PWA" claim, this is the
   single highest-value fix for the next run — likely needs either a
   `@media (max-width: ...)` rule that stacks the two `st.columns()` panels
   vertically, or collapsing the Atlas panel behind a toggle below a
   width threshold. Left unfixed this run rather than risk an untested,
   under-verified structural CSS change this late in the cycle — see
   guardrail "be conservative where damage is possible."

3. **Minor: the sticky "Ask Atlas anything..." command bar at the bottom
   of every page stays dark-themed even when Arctic (Light) is active.**
   Cosmetic, not a blocker, but visible in every light-theme screenshot.
   Logged for the same next-run CSS pass as #2.

## Interview-panel weak spots

- Auto Analyst and Atlas already cover "agentic EDA" well, but nothing
  before this run made a *falsifiable claim* and then *tested* it —
  everything was descriptive (distributions, correlations, plans) rather
  than confirmatory (a stated hypothesis with a verdict). This is exactly
  the kind of hypothesis-driven-analysis + statistical rigor combination a
  data-scientist interview panel probes for, and was the gap this run's
  Hypothesis Engine closes.
- Anomaly Detection had a fixed 5% contamination rate with no way to tune
  it and no synthesis of *why* the flagged set matters as a whole (only
  per-row reasons) — both called out explicitly in the README's own
  Roadmap section. Closed this run.
