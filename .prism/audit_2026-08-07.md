# Prism Audit — 2026-08-07

First run of the memory-tracked autonomous routine (`.prism/routine_log.md` did
not exist before this run). The repo's git history shows the app is already
very mature — Auto Cleaner, India Mode/Indian PII Vault, Hell Mode, a SQL Lab
DuckDB workbench, ML Lab with SHAP, Stats Lab, Drift, Auto Analyst (agentic
plan → execute → synthesize), a full Atlas voice copilot (intent routing,
TTS, neuron-network HUD background, Demo Mode, Story Mode) all already ship.
**Note for future runs:** this is a Streamlit app (`app.py`, `modules/*.py`)
with a hand-built glassmorphic "HUD" CSS theme (`modules/theme.py`), not a
React/Next.js shell — the routine's boilerplate context describing a
Next.js PWA shell does not match the actual codebase. Trust the repo, not
the boilerplate, in future runs.

## What was exercised

Launched `streamlit run app.py` locally, loaded the bundled Sales sample,
and drove the Overview tab (including the new Hypothesis Generator) through
Playwright at desktop (1440×900) and mobile (390×844) viewports, dark
(Prism HUD) and light (Arctic) themes.

## Findings

### 1. [HIGH] Mobile viewport layout breaks once a dataset is active
At 390px width, the landing screen (no dataset loaded) is correctly
responsive — sample cards stack in a single column. But the moment a
dataset loads, the three-way layout (sidebar + main content + Atlas panel)
does **not** reflow: the main content column gets squeezed to a ~30px
sliver (its text wraps one character per line) while the Atlas panel keeps
its full width and covers most of the screen. This makes every tab —
Overview, Clean, Hell Mode, everything — effectively unusable on a real
phone-width viewport once you're past the landing screen, which undercuts
the "installable on phone" PWA claim. Root cause not fully isolated this
run (native `st.columns()` are in use per the DOM — `stColumn`/
`stHorizontalBlock` — so this is likely a Streamlit responsive-wrap
interaction with the Atlas panel's neuron-canvas or a min-width somewhere
in `modules/theme.py`/`modules/atlas.py`, not a hardcoded width I could find
by grep). **Not fixed this run** — a proper fix needs a dedicated pass:
isolate the exact CSS/column causing the non-wrap, fix it, then re-screenshot
every tab at mobile width in both themes per Phase 5's checklist, which is
more than a "small fix" slotted in alongside a feature build. Flagged as
next run's top priority.

### 2. [LOW] Bottom chat input bar keeps dark styling in the light theme
The persistent "Ask Atlas anything…" input bar at the very bottom of the
page stays on a dark background with light placeholder text when the Arctic
(Light) theme is active — every other surface switches correctly. Minor
contrast inconsistency, not a functional break. Pre-existing, unrelated to
this run's change.

### 3. [INFO] `google-generativeai` (the pinned Gemini SDK, 0.8.6) is EOL upstream
Importing it now prints: *"All support for the `google.generativeai`
package has ended... switch to the `google.genai` package."* The app still
works today. Migrating is a real dependency swap touching every Gemini call
site (`modules/ai_analyst.py` and everything that calls through it) — out of
scope for a single run per the "no architecture rewrites" guardrall, but
worth a dedicated future run since upstream has stopped shipping fixes.

### 4. No `tests/` directory existed before this run
There's an `eval/` folder (LLM-output eval harnesses) but zero unit tests
for the deterministic analysis logic — profiling, cleaning, stats, ML
baselines, anomaly detection, drift, all untested by a real assertion
suite. This run adds `tests/` with the first suite (for the new Hypothesis
Engine); backfilling coverage for the existing modules is a strong
candidate for a future run — it's high signal for an interview portfolio
("does this have tests?") and currently the honest answer was no.

## Not re-tested this run
Every other tab (Clean, Hell Mode, Combine, Visualize, SQL Lab, AI Analyst,
Auto Analyst, Stats Lab, Forecasting, Clustering, Domain Lens, Geo Lens, ML
Lab) was not re-driven end to end this run — prior runs' git history
suggests they were hardened individually (see commit log: SSRF/LFI sandbox
fixes, corpus gauntlet hardening, cluster naming fixes, etc.). This audit
focused on Overview (where the new feature lives) plus the landing screen
and cross-theme/viewport spot checks. A full click-through of every tab is
a good candidate for a dedicated future audit-only run.
