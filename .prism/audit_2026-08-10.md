## Confirmed: "82 new unit tests" from the 2026-08-07 Run 2 log entry are not pytest tests

`CHANGELOG.md` and `routine_log.md` both describe Auto-Insight Engine (23),
Regression Diagnostics (33), and STL Decomposition (26) as having "new
tests." In reality these live in `eval/*_eval.py` as custom `check()`-based
scripts run via `python eval/auto_insights_eval.py`, not `tests/*.py` files
pytest collects. Running `pytest tests/` today picks up 27 tests total
(now 44 after this run), none of which touch those three modules. This
isn't a regression from today, but it means `pip install -r
requirements-dev.txt && pytest` — the documented way to verify Prism —
silently gives zero coverage signal for three shipped features. Left as a
backlog item (see run report) rather than converting all ~82 checks this
run; that's real, contained work but not this cycle's priority.

## Environment finding: `_cffi_backend` missing breaks pytest collection

Fresh from `requirements-dev.txt` alone, `pytest tests/` crashed at
collection with `pyo3_runtime.PanicException: Python API call failed` /
`ModuleNotFoundError: No module named '_cffi_backend'` — `cryptography`
(a transitive dependency pulled in by `google-generativeai`) needs `cffi`
installed, and `requirements-dev.txt` doesn't pin it. `pip install cffi`
fixes it. Worth adding `cffi` to `requirements-dev.txt` explicitly so a
clean `pip install -r requirements-dev.txt && pytest` doesn't fail for the
next contributor — flagged here, small enough to fold into next run's
first PR rather than touching dependency pins mid-feature-run today.

## New finding: Arctic (Light) theme doesn't fully repaint dataframes/charts/Atlas panel

Captured while taking this run's light-theme screenshots (see
`feature_selection_desktop_light.png`, `anomaly_narration_desktop_light.png`):
switching to "Arctic (Light)" repaints the page background and sidebar
correctly, but `st.dataframe` tables, Plotly chart backgrounds, and the
Atlas side panel's card/button chrome stay dark. Not introduced by this
run's features — every dataframe/chart on the page shows the same
inconsistency, including ones untouched today — but this run's two new UI
elements (feature-ranking table, anomaly narration panel) inherit it
directly. Root cause is almost certainly `apply_plotly_theme()` /
dataframe styling not being wired to the same theme key the CSS injection
uses, or a set of hardcoded dark colors in `theme.py`'s non-default theme
CSS. Flagged for a dedicated theming pass — not fixed today (touches
shared theme plumbing used by every chart/table in the app, higher risk
than this run's budget for an unplanned fix).
