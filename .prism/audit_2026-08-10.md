## Carried-forward findings, re-verified

1. **Mobile Atlas panel overlap (still open).** `modules/theme.py` has
   exactly one `@media` query in its injected CSS
   (`prefers-reduced-motion`) — zero responsive breakpoints for viewport
   width. The 2026-08-07 Run 2 finding that the Atlas side panel doesn't
   reflow under ~640px and squeezes main content into an unreadable strip
   is confirmed still present (grep-verified, no CSS changed that area
   since). Selected as this run's small-fix candidate.
2. **`google-generativeai` deprecation (still open, still not urgent).**
   `modules/ai_analyst.py:35` raises a `FutureWarning` on import — SDK is
   past EOL upstream. Confirmed still present. Not touched this run per
   the last two runs' explicit "needs its own dedicated run" guidance —
   this file is imported from `ai_analyst.py`, `auto_analyst.py`,
   `atlas.py`, `auto_insights.py` (narration) and touching the client
   surface needs a full regression pass across all four, not a rider on a
   feature-shipping run.
3. **`eval/*.py` harnesses are invisible to plain `pytest`.** `pytest.ini`
   sets `testpaths = tests`, so the 82 checks in `eval/auto_insights_eval.py`,
   `eval/regression_diagnostics_eval.py`, and `eval/stl_decomposition_eval.py`
   never run via `pytest` — only via `python eval/<file>.py` directly (as
   done above). This is a deliberate split (eval/ predates pytest.ini and
   has its own `check()` harness, some evals need a live Gemini key), but a
   plain `pytest` run silently under-reports coverage to anyone (including
   a future routine run or an interviewer) who just types `pytest`. Not a
   functional bug — no code path is broken — so left as a documented gap
   rather than a rushed migration; flagging for a future run to either (a)
   convert eval/ files with no Gemini dependency into real pytest files
   under tests/, or (b) add a Makefile/README target that runs both.
