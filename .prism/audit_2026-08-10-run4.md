## New finding — mobile layout squish is bigger than the Atlas panel alone
2026-08-10 Run 3 found and fixed a CSS bug (orb invisible in the side
panel) and flagged, but did not fix, "the Atlas side panel doesn't reflow
and overlaps/squishes main content into an unreadable strip" at ~390px.

This run selected a fix for that (see routine log / CHANGELOG): the panel
no longer renders as a `position: fixed` 328px overlay below 640px
viewport width — confirmed via Playwright screenshot comparison against
the pre-fix `main` branch (`.prism/runs/2026-08-10-run4/`), where the
panel visibly ate ~85% of a 390px-wide screen and left main content
wrapped one character per line.

**However**, verifying that fix surfaced a **second, independent, deeper
bug**: even with the panel no longer overlaying, main content at 390px
still renders compressed into narrow vertical strips
(`.prism/runs/2026-08-10-run4/08_overview_mobile_dark.png` and `09_...png`).
Debugged via `getBoundingClientRect()` on live DOM nodes — reproduced
identically on `main` (pre-run4) at the same viewport, confirming this is
**pre-existing and not caused by this run's changes**, but also **not
fixed by this run's Atlas-panel-specific CSS fix** — it's a separate root
cause (something in the general column/content layout, not the side
panel) that needs its own dedicated investigation, not a quick patch
alongside an unrelated feature. Logged in the routine log and research
table as a next-run candidate rather than guessed at further here — do
not assume the Atlas panel fix "fixed mobile," it only fixed the specific
overlay symptom.
