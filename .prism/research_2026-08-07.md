## Why #1 was picked, #2/#3 deferred

- **#1** is the only candidate that is simultaneously: (a) squarely the
  cycle's mandated priority theme (agentic AI analysis: "self-verifying
  analysis agents" is named explicitly in the routine's own Phase 2.4),
  (b) genuinely high technical-depth (statistical significance testing,
  effect sizes, hypothesis-test dispatch by column type — the actual
  substance of a data-scientist's job, not UI polish), (c) low risk (no
  new Gemini calls, no new dependency, pure function, fully unit-testable
  without a live API key), and (d) reuses existing, already-hardened
  infrastructure (`stats_lab.py`) instead of adding a new subsystem —
  consistent with this codebase's own stated convention of not
  duplicating plumbing.
- **#2** (Atlas proactive insights) is a legitimate Atlas-copilot-track
  slice for a *future* run — deferred this cycle to keep the diff surface
  small and reviewable, and because it has a real design risk (unprompted
  chat interruptions need a relevance/frequency filter to not feel like
  spam) that deserves its own focused pass rather than being bolted on
  alongside #1.
- **#3** (Polars) is explicitly an architecture change per the routine's
  own guardrails ("no architecture rewrites... write it as a proposal in
  the report instead") — logged here, not built.
- **#6/#7** are real but non-feature tech debt; logged for a future
  dedicated "hardening" run rather than mixed into a feature cycle.
