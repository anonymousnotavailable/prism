# Research — 2026-08-07

Four source classes, synthesized. Full search trail in `routine_log.md`.

## Industry practice
- SQL remains the single most-tested data-analyst skill in 2026 interviews;
  Python/pandas sits at ~41% of postings, statistics and "take messy data →
  find the real question → explain in plain language" are called out
  explicitly as what employers screen for. ([testleaf.com](https://www.testleaf.com/blog/data-analyst-job-description-2026/), [dataquest.io](https://www.dataquest.io/blog/data-analyst-skills/))
- Prism already covers SQL (SQL Lab/DuckDB), pandas cleaning, dashboards,
  and plain-English narration everywhere. The gap: *testable* statistical
  claims, not just descriptive summaries — "prove it with a p-value," not
  "here's a chart."

## Competitor tools
- The AI-analysis landscape has split into three lanes: chat-first
  (ChatGPT Advanced Data Analysis, Julius), notebook/workspace (Hex,
  Deepnote), and embedded copilots (Databricks Assistant). Solo users favor
  chat-first tools; teams favor Hex/Deepnote for governed, shared work.
  ([gudz.ai](https://gudz.ai/posts/ai-data-analysis-tools-2026), [deepnote.com](https://deepnote.com/compare/juliusai-vs-deepnote))
- None of the surveyed tools foreground *automated hypothesis testing with a
  real significance test attached* as a one-click, ranked feature — they
  generate charts/narratives, and leave "is this actually significant" to
  the user asking follow-up questions. That's the gap Prism's new
  Hypothesis Generator targets directly.

## Ecosystem tech
- Consensus for 2026: a converging "DuckDB + Polars + Pandas" stack, Arrow
  as the shared memory format; Polars is the recommended *default for new*
  ETL/analytics work, but pandas stays the right choice for
  scikit-learn-dependent ML workflows and small/medium interactive
  analysis — which describes Prism's current workload closely. ([flowfile.io](https://flowfile.io/blog/polars-vs-pandas-2026/), [dev.to](https://dev.to/dataformathub/python-data-processing-2026-deep-dive-into-pandas-polars-and-duckdb-2c1))
- Prism already has DuckDB (SQL Lab). A future run could evaluate Polars as
  an opt-in fast path for large-file loading (`data_engine.py`), not a
  pandas replacement — that's an architecture decision for its own
  dedicated run, not a drive-by swap.
- PyGWalker: a Tableau-like drag-and-drop visual explorer over a DataFrame.
  Prism's Visualize tab already covers manual charting; PyGWalker would be
  additive polish, not core depth — lower priority than statistical rigor.

## Agentic EDA research
- Current LLM-based data-science-agent surveys (arXiv 2510.04023,
  QUIS/2410.10270) describe the frontier as: plan → generate code → execute
  → self-verify → narrate, with **full-pipeline autonomous success rates
  still below 1%** on hard benchmarks — the honest state of the art is
  narrow, verifiable slices (a single well-scoped statistical claim checked
  against real math), not open-ended "analyze everything." ([arxiv.org](https://arxiv.org/html/2510.04023v1))
- This directly informed this run's design choice: the Hypothesis Engine
  never lets an LLM decide what's "significant" — Gemini (if configured) only
  phrases an already-computed, scipy-verified result. The verdict is 100%
  deterministic and reproducible with zero API key, same guarantee Auto
  Cleaner already established for its SAFE/REVIEW split.

## Not selected this run, and why
- **Polars fast-path** and **Atlas proactive insights** are both strong
  next-run candidates but were held back deliberately: Polars is an L-effort
  dependency change better done in its own focused run with real
  before/after perf benchmarks, and the Atlas track's own rule caps it at
  one incremental slice per run — this run's core-capability feature
  (Hypothesis Generator) already fills the "one feature per run must serve
  agentic AI analysis" requirement, and stacking a second higher-risk
  feature in the same run raises the odds of shipping something half-verified.
- **google-generativeai → google.genai migration**: real and now-evidenced
  (EOL banner), but touches every Gemini call site in the app — flagged as
  its own dedicated future run per the "no architecture rewrites" guardrail,
  not bundled in as a "small fix."
