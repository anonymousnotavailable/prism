## Sources swept

- **Industry practice**: current DS/analyst job postings consistently list
  "statistical rigor" and "hypothesis testing" as a distinct skill from
  "dashboarding" — multiple-testing correction specifically comes up in
  interview loops at the senior-analyst level, not just ML roles.
- **Competitor tools**: Julius AI, Hex, Deepnote, ChatGPT Advanced Data
  Analysis. ([Julius AI vs Deepnote](https://deepnote.com/compare/juliusai-vs-deepnote),
  [Hex competitors](https://julius.ai/articles/hex-competitors),
  [2026 platform comparison](https://nomadlab.cc/blog/2026/05/ai-data-analyst-platforms-2026-hex-julius-cortex-genie-thoughtspot)).
  All four generate insights/narration from natural-language prompts; **none
  of the surveyed tools' marketing foregrounds a statistical-correction
  step** — they sell "ask a question, get a chart + narration," not
  "here's what's actually statistically defensible." That's the gap Prism's
  Hypothesis Engine (shipped this run) targets directly: propose-then-prove
  with a stated correction method, not just an LLM asserting a conclusion.
- **Ecosystem tech**: polars/DuckDB adoption keeps climbing per package
  download trends; Prism already has a full DuckDB-backed SQL Lab
  (shipped a prior run) — polars is not yet integrated (still pandas-only
  compute), noted as backlog below, not attempted this run (would touch
  every module's dataframe assumptions — too broad for one cycle).
- **Agentic EDA research**: [LLM-Based Data Science Agents survey](https://arxiv.org/html/2510.04023v1)
  and [QUIS: Question-guided Insights Generation for Automated EDA](https://arxiv.org/pdf/2410.10270)
  both frame the state of the art as "propose analyses via LLM, execute
  deterministically, synthesize" — which is exactly Auto Analyst's existing
  shape (shipped previously) and the pattern this run's Hypothesis Engine
  extends into statistical testing specifically. The survey is also blunt
  that full-pipeline autonomous correctness is still low (EXP-Bench:
  <1% full-pipeline success) — reinforcing that Prism's "Python decides the
  math, LLM never does" split (autocleaner's SAFE/REVIEW, now
  hypothesis_engine's propose/prove) is the right conservative shape, not
  an under-ambitious one.

## Why Hypothesis Engine over the alternatives this cycle

The priority theme this run is agentic AI analysis, and the strongest,
most defensible depth signal available was statistical rigor specifically
— multiple-testing correction is the kind of detail that separates "used
an LLM to write some pandas" from "understands why testing five hypotheses
on one dataset without correction is a false-positive factory." Auto
Analyst and Atlas already cover the "propose a plan, run it, narrate it"
shape; Stats Lab already covers "run one correct test." Nothing in the app
closed the loop between the two — a user could not ask "what's worth
testing here" and get back statistically defensible answers. That gap, not
effort or competitor-parity, drove the pick.
